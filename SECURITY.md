# Безопасность Home Center

Home Center следует fail-closed модели: неизвестное, stale, неподтверждённое или противоречивое состояние не должно трактоваться как безопасное или успешное.

## Основные правила

- Храните пароли, ключи и секреты вне исходного кода и release-архивов, с минимально необходимыми правами доступа.
- Используйте TLS для сетевых интерфейсов; peer-соединения должны использовать предусмотренную взаимную аутентификацию.
- Привилегированные системные действия допускаются только через типизированные и ограниченные действия; произвольная shell-команда не является штатным пользовательским API.
- Изменения состояния должны проходить Identity/RBAC, точный план/Desired State, подтверждение, Job, post-condition verification, Audit/evidence и recovery/rollback при необходимости.
- Значения секретов не должны попадать в Audit, диагностические материалы или пользовательские evidence.
- External publication, firewall/NAT и удалённый доступ не должны включаться неявно.
- Backup считается пригодным только при наличии проверяемого restore/recovery процесса.

## Локальный администратор

После чистой установки используется `admin` / `admin`; при первом входе пароль необходимо сменить, и до смены обычная работа запрещена. Обновление не должно сбрасывать пользовательский пароль к значению по умолчанию.

## Сообщение об уязвимости

Не публикуйте секреты, персональные данные или эксплуатационные детали уязвимости в открытом issue. Передавайте сведения владельцу продукта по конфиденциальному каналу, достаточному для безопасной проверки и исправления.
